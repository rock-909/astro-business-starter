# 设计参考

本文记录已经判断值得借鉴的设计细节、原则和使用边界，服务当前站及工业 B2B 派生站。

本文不是品牌规范，也不是组件库。权威关系如下：

- [设计真相](设计真相.md)：当前项目必须遵守的设计规则；
- [README 的派生站点改哪里](../../README.md#派生站点改哪里)与 [LAUNCH.md](../../LAUNCH.md)：派生站改哪些文件、如何验证和上线；
- 本文：外部参考中值得保留的设计证据和可迁移原则。

外部网站只提供证据和启发，不直接决定业务内容、SEO、页面结构或品牌视觉。任何参考进入实现前，都要回到买家任务、产品事实和现有 Token 验证。

这些案例按需要查阅，不是设计前必须遍历的清单；工业 B2B 映射仅适用于对应业务。

## 使用方法

每次引入一个参考时，先回答：

```text
它解决了哪个用户问题？
它体现了什么设计原则？
能否落到现有页面、Token 或组件？
是否会增加没有业务收益的复杂度？
如何验证它在本项目中有效？
```

满足以下任一条件，直接不采用：

- 无法映射到当前买家的真实任务；
- 只能复制外观，无法解释行为或内容价值；
- 无法落到现有页面、Token 或组件；
- 需要新增依赖、客户端脚本或 island、长期维护成本，但没有明确收益；
- 会隐藏产品事实、规格、交付边界或询盘入口。

## 参考分层

| 类型 | 主要回答 | 可以借鉴 | 不能证明 |
| --- | --- | --- | --- |
| 真实产品流程 | 用户如何完成任务 | 信息架构、步骤、反馈 | 工业采购一定采用同样流程 |
| 页面叙事 | 内容如何被组织和展开 | 标题、比例、节奏、CTA | 转化效果和业务真实性 |
| 设计模式 | 某个细节为什么有效 | 状态、错误、展开、反馈 | 适合所有业务场景 |
| 设计系统 | 规则如何保持一致 | Token、组件状态、命名 | 本项目应直接采用其视觉语言 |
| 交互指南 | 控件如何被理解和操作 | 可发现性、反馈、可恢复 | SEO、产品定位和内容策略 |
| 动效参考 | 状态如何连续变化 | 过渡、反馈、层级 | 动画数量越多越好 |
| 质量标准 | 如何验收 | 无障碍、性能、稳定性 | 设计品味和品牌判断 |

## Apple Human Interface Guidelines

来源：[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)

### 值得借鉴

- **可发现**：用户能看出什么可以操作，以及操作后会发生什么；
- **反馈**：筛选、提交、下载、切换和展开都要给出清晰结果；
- **可恢复**：错误提示说明问题、原因和修复方式；
- **连续性**：界面变化保持位置、层级和因果关系；
- **减少认知负担**：只在需要时展示复杂选项；
- **可访问**：键盘、焦点、文字大小、对比度和减少动态效果不能作为后补；
- **动效有目的**：解释状态、层级或导航，不延迟用户任务。

### 工业 B2B 转化

| HIG 原则 | 工业站用法 |
| --- | --- |
| Feedback | 询盘提交、筛选结果、下载和主题切换明确显示结果 |
| Discoverability | CTA、规格入口、图纸下载和可展开内容清楚可见 |
| Error recovery | 表单错误就地说明，保留用户已填写内容 |
| Progressive disclosure | 先显示核心规格，复杂定制条件按需展开 |
| Accessibility | 规格表、表单、状态和焦点在键盘和窄屏下成立 |
| Motion | 用短过渡表达变化，不用页面级 reveal 隐藏内容 |

### 不直接复制

- iOS 的导航、Tab Bar、手势和系统控件外观；
- Apple 的字体、圆角、玻璃效果和品牌黑白配色；
- 面向消费设备的交互假设；
- 任何会替代工业产品事实的情绪化表达。

## Vercel、Cursor、OpenAI、Linear、IBM

这些网站不按业务行业复制，只作为跨产品的最大公约数参考。

### 值得借鉴的共同点

#### 克制

- 页面保留少量真正重要的视觉重点；
- 不用连续动画、装饰性渐变和多余卡片填满空间；
- 让高质量排版、对齐和留白承担主要视觉工作。

#### 强层级

- 首屏有明确主标题和核心结论；
- 主要行动与次要行动有清晰差异；
- 复杂信息按层级展开，不把所有内容挤在同一视觉平面。

#### 系统一致

- 颜色、间距、边框、圆角和控件状态有稳定规则；
- 相同语义的组件在不同页面保持相同行为；
- 页面差异来自内容和任务，而不是随意换主题。

#### 状态清晰

- 加载、成功、失败、空结果和禁用状态可理解；
- 用户始终知道系统正在做什么；
- 重要任务不依赖 hover、自动播放或动画完成。

### 工业 B2B 转化

```text
中性画布
→ 清晰产品结论
→ 少量品牌色强调
→ 规格和证据分层
→ 明确询盘动作
```

这些原则可以继承；具体品牌色、页面比例、动画形式和视觉素材不能直接复制。

## 可采用模式：编辑式产品展示

本节列出候选页面模式和工业 B2B 用法，不表示本项目已经实现这些栏目或效果。

### 值得借鉴

- **编辑化布局**：页面像一篇有节奏的长篇内容，而不是由大量同质卡片堆成；
- **大标题锚点**：用少量超大标题建立区块识别，再用短说明解释上下文；
- **Sans + Mono 角色分工**：Sans 用于标题和正文，Mono 用于导航、分类、日期、阅读时长和技术元数据；
- **粗边框建立秩序**：用边界线、分栏线和留白表达区块关系，减少对阴影的依赖；
- **大比例图片与内容并置**：图片承担识别和吸引注意，文字承担项目说明和行动入口；
- **元数据提高可浏览性**：分类、日期、阅读时长和标签帮助用户快速判断内容；
- **图片状态轻量变化**：灰度图片在 hover 时恢复颜色并轻微放大，提供反馈而不抢夺内容；
- **栏目化内容资产**：作品、实验、文章、演讲和过程分别组织，形成持续更新的内容结构。

### 工业 B2B 转化

| 作品展示类模式 | 工业 B2B 站 |
| --- | --- |
| Selected Works | Featured Products / Case Studies |
| Vibe Coding | Engineering Experiments / Technical Capabilities |
| Writings | Technical Resources |
| Speaking | Certifications / Industry Presence |
| About the Process | Manufacturing / Delivery Process |
| Mono 元数据 | 型号、规格、单位、版本、适用行业和更新时间 |

适合将这种编辑化节奏用于首页重点产品、案例、应用和技术资源；产品详情页仍然优先保证规格、交付边界、证据和询盘入口。

### 不直接复制

- 参考站的荧光绿或其他品牌色；派生站自行选择品牌颜色，并保持语义 Token、对比度和状态可辨识；
- 个人名字式的超大 Hero；工业站首屏必须说明产品、应用或供应能力；
- 个人博客栏目和职业叙事；改为产品、应用、工程、资源、案例和交付内容；
- 极端留白和全屏作品集比例；留白必须服务采购判断；
- 仅依赖 hover 的图片变化；触屏和无 JavaScript 时内容仍需完整可读。

## 设计系统和组件资源

适用参考包括 Component Gallery、Design System Checklist、WAI-ARIA Authoring Practices 等；Base UI、React Aria、Radix、ReUI 是 React 组件库，本项目没有 React，只借鉴它们的行为、状态和无障碍做法，不引入代码。

### 使用顺序

```text
先确认用户任务和组件行为
→ 横向比较成熟系统
→ 选择现有项目能承接的基础实现
→ 使用本项目 Token 和内容规范收敛
→ 检查状态、无障碍、响应式和性能
```

### 采用边界

- 行为复杂的控件优先使用项目已有的本地实现（`src/components/` 下的组件和浏览器脚本）；
- 普通文本、列表、规格表、按钮和表单优先使用原生 HTML；
- 外部组件代码不能直接成为项目设计系统；
- 一个组件只有一个真实调用方时，不为“以后复用”增加抽象；
- 引入新依赖前必须指出真实消费者和可复现收益。

## 采用参考的执行要求

模块组装、Agent 输入、视觉候选比较、独立双通道审查和 AI/Figma 使用边界已集中到[设计真相的方案与审查](设计真相.md#方案与审查)。整体视觉方案需独立复核，小范围调整按影响检查；视觉参考不能替代内容批准和运行时验证。

## 动效资源

适用参考包括 Transitions.dev、Motion Primitives、Animate UI，以及经过筛选的品牌动效案例；后两者基于 React，只借鉴过渡的时序和状态，用 CSS 实现。

### 采用顺序

```text
先确认状态变化
→ 选择最短、最轻的过渡
→ 优先 CSS 和现有浏览器能力
→ 支持 prefers-reduced-motion
→ 检查输入阻塞、布局稳定性和移动端性能
```

### 工业站优先级

1. 询盘提交成功、失败和进行中；
2. 产品筛选、展开和切换；
3. 主题切换和焦点反馈；
4. CTA hover / focus；
5. 低频品牌节点的轻量氛围动效。

不要为首屏、规格、证据或询盘入口增加必须等待的 reveal 动画。
