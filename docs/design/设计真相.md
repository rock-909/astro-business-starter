# 设计真相

## 当前方向

底座提供首页、联系与法务骨架和可访问的询盘路径，不预设业务叙事、产品模型或品牌视觉候选。派生站按真实买家任务、品牌和证据决定页面结构与视觉方向。

## 硬边界

- 主内容和主要 claim 默认可见，不依赖 JavaScript reveal；
- 设计优先复用正式 UI 入口：`src/components/` 下的现有组件和 `src/styles/global.css` 里的组件类（如 `.button`、`.field`）；
- 颜色、网格、页面模式和动效由本文负责，代码级组件边界由 [UI 实现规则](../../.claude/rules/ui-i18n-consent.md) 负责；
- 不为了高级感增加长动画、客户端脚本或 island、新依赖；
- reduced-motion、键盘焦点、对比度和窄屏布局是基本要求。

## 已确认的共同原则

| 原则 | 当前要求 |
| --- | --- |
| 内容先于装饰 | 首屏先回答“这是什么、适合谁、下一步是什么”；标题和核心结论先于图片、渐变和动效。装饰不能替代产品事实、规格、证据或交付边界；视觉元素可以服务品牌识别、情绪与阅读引导；按这些作用和性能、可访问性成本判断保留与否，不因不承载文字信息就删除，也不为装饰而装饰。 |
| 一个区块回答一个主要问题 | 区块应回答产品身份、适用场景、规格匹配、配置、交付、可信证据或询盘动作；没有明确问题时，不因为“页面看起来完整”而保留。 |
| 层级与行动 | 用字号、字重、间距、位置和对比度建立层级；一个页面只保留一个主要行动，次要动作降低视觉权重但保持可发现性。不同时堆叠过大的字号、粗阴影、强渐变、厚边框和多种卡片。 |
| 留白与窄屏 | 区块间距表达内容关系，相关内容靠近，不相关内容拉开。留白不能使首屏缺少产品事实或 CTA；窄屏保留阅读顺序和触控空间，不机械缩小桌面。 |
| 颜色语义 | 品牌颜色由派生站选择，通过语义 Token 表达主按钮、焦点和信息强调；主按钮用品牌色（浅色深一级品牌色配白字、深色亮品牌色配深色字），描边按钮（次级动作）、导航、页脚和正文链接保持中性色。成功、警告、错误等状态不能只依赖颜色。换肤须保持对比度、焦点与状态可辨识。 |
| 行为先于表面 | 按语义结构 → 默认行为 → 键盘与焦点 → 响应式边界 → 状态反馈 → 视觉 Token → 动效实现。外部组件正式使用前，必须统一项目 Token、内容结构、状态、响应式和无障碍行为。 |

## 设计系统

`src/styles/global.css` 顶部的 token 块是网站整体视觉主题的运行真相，也是 Agent 接到“换品牌风格”任务时的第一入口。它包含少量视觉原料（品牌与中性色阶）、组件实际使用的语义角色，以及圆角、控件高度和阴影等少量全局质感参数；浅色 `:root`、`[data-theme='dark']` 和系统深色媒体查询三块一起改，`npm run test:browser` 检查两个深色块一致及主要文字对比度。同一文件的其余部分维护全局 focus、reduced-motion、动画、基础样式和组件样式；项目不使用 Tailwind。

Token 是方便修改的入口，不是限制层：整体换肤先改 `global.css` 的 token 块；组件结构或变体（如 `.button.outline`、`.button.ghost`）改 `src/components/*.astro` 和 `global.css` 里对应的组件类；页面需要特殊设计时直接改 `src/pages/`、`src/layouts/SiteLayout.astro` 或领域组件。组件默认使用背景、正文、弱文本、边框、品牌强调、状态和反差文字等语义角色，不直接引用底层视觉原料，也不在页面复制颜色、圆角、阴影或近似 token。

底座当前没有网格装饰；派生站加入网格时，只用于建立内容节奏和装饰锚点，不得遮挡正文、焦点环或主要 CTA。设计系统变化至少检查桌面/移动布局、主题对比度、键盘焦点和首屏内容可见性。

## 页面模式

页面按真实任务组织标题、正文与下一步动作。派生站需要产品页时，先说明产品身份和适用场景，再呈现规格、图示、下载和询盘入口；示意图不能冒充工程证据。

CTA 要说明下一步动作。表单只保留必要字段，错误就地、可读、可恢复。窄屏优先保证正文、规格、键盘顺序和触控目标，布局不能依赖 hover，主要入口不能被动效或 sticky 装饰遮挡。

底座不预设产品目录、产品模型或七类采购区块。派生站确有产品详情需求时，再按真实买家任务决定产品事实、应用场景、规格、材料、配置、交付与证据的组织方式；内容入口由该业务模型明确，不能把填写说明当真实参数。

## 导航二级菜单

`src/site-routes.ts` 的 `navMenus` 登记了菜单时按 Vercel 的做法渲染；派生站只改 `navMenus` 和每种语言 `messages.json` 的 `navigation.menus`，不另写组件。底座不带示例二级菜单（`tests/derived-site.mjs` 的派生站夹具带一个）。

- 桌面：顶层项是带小箭头的按钮，本身不跳转；展开后是贴在页头下方的整宽面板，一组一栏，栏首是灰色小标题，下面是黑色链接、无底色。鼠标悬停只在文字下出现浅灰细下划线（`--nav-link-underline`），文字颜色不变，↗ 不画线；键盘焦点只显示焦点框。站外链接带 ↗、新标签页打开。展开的顶层项变黑，其余保持灰色，面板下方页面淡出。
- 交互：悬停约 100ms 展开、离开约 150ms 收起；点击或 Enter、Space、↓ 展开，键盘展开时焦点进入第一项；Esc 收起并回到按钮；面板内 ↑↓、Home、End 移动，顶层 ←→ 在各项间移动焦点。面板内有键盘焦点时，指针离开或移到其它顶层项都不收起、不切换；焦点进入二级菜单按钮或面板即取消待执行的悬停计时。焦点离开导航即收起（Vercel 不收起，这里避免面板遮住焦点）。
- 手机：抽屉里用原生 `<details>` 折叠展开，同一时间只展开一项。
- 二级链接始终在预渲染 HTML 里（脚本接管后关闭时 `hidden`；无 JavaScript 时由 CSS 在悬停或焦点时显示），不执行 JavaScript 的搜索引擎和 AI 抓取也能读到。

## 动效

动效只能解释状态、层级或导航路径。优先 CSS、现有 state 属性和浏览器能力，不为“高级感”增加页面级 reveal、长 duration、新 motion 依赖、`client:*` island 或整页客户端脚本。

静态营销内容保持预渲染的静态 HTML，首屏 claim 默认可见，动效失败时内容仍完整可读。必须尊重 prefers-reduced-motion，避免破坏键盘焦点、读屏顺序、布局稳定性和 LCP；动效变更至少检查无 JS、reduced-motion、窄屏、键盘和真实浏览器行为。

截图和读代码看不到中间态，动效变更以逐帧录制作为验收证据：覆盖触发前到稳定后的全过程，常规与 reduced-motion 各一份，逐帧确认没有跳动、闪烁、遮挡或布局位移；Playwright 按帧截图即可，证据附在 PR 或变更记录，不提交进仓库。

## 方案与审查

### 模块与输入

AI 和外部模块只提供原料，不能凭空决定页面结构或品牌风格。先检查现有页面和组件；已有合适实现时直接复用。只有方向未确定或现有实现不能解决问题时，才比较参考、提取行为和结构，再接入现有 Token 与组件。

- 适合模块组装：产品卡片、规格表、参数对照、应用场景、材料说明、配置选项、证据列表、询盘表单、筛选控件、状态反馈、主题切换、展开/收起、下载反馈和错误提示。
- 不适合直接拼装：首页 Hero、品牌核心叙事、产品定位、应用说明、交付边界、认证与证据表达、询盘字段和地区内容。它们必须来自业务事实、买家任务和证据，不能从组件市场推导。
- 给 Agent 的输入至少包括：页面任务和买家、具体 UI 问题、当前设计内核、可参考模块、必须继承的 Token/组件/行为、不能复制的品牌外观，以及无障碍、响应式、性能和 no-JS 条件。
- 使用外部参考时说明适用取舍；不要直接复制完整页面、完整组件库或未经筛选的代码。

### 视觉候选与 AI/Figma

已有明确设计或小范围调整时，直接沿用，不走下面的设计方向环节；只有客户 VI 不算已有明确设计。派生站方向不明确时，按以下环节定方向；这是待首个真实派生站试行的流程，试行后按结果修订。

| 步骤 | 做什么 | 产出 |
| --- | --- | --- |
| 0. 输入 | 内容包事实、买家任务、客户已有品牌资产、3–5 个竞品站、本文硬边界、本站行业的[金标样例](设计参考.md#金标样例库)（由 Owner 为本站挑选）；Owner 提供品味记录时一并读取 | — |
| 1. 文字定方向 | 3–5 个品牌形容词，各配一句“形容词 → 具体视觉动作”；竞品和本品类 AI 默认长什么样（作反参照）；图片承担什么角色。客户事实由业务 owner 确认 | 半页文字 |
| 2. 三个方向 | 每个方向从最接近的金标样例出发，按品牌与内容改写；三者至少在明暗、字体、首屏构图、信息密度中的三项不同，换个行业仍成立就重做；有客户 VI 时锁定色彩、字体和 logo，改为至少在首屏构图、信息密度、图片角色三项上不同，盲选仍必需；有品味记录时至少一个方向故意不按既往偏好。每个方向写成风格契约：Token 草案、构图规则、图片角色、密度、优化了什么与牺牲了什么 | 契约 + 用真实内容渲染的首屏、参数最密集区块和 375px 窄屏 |
| 3. 并排检查 | 由非生成者对照金标样例和[命名失败清单](#命名失败清单)逐条检查，像另一个方向的重做；跑对比度、溢出、窄屏等确定性检查；不打审美总分 | 对比页 |
| 4. 盲选（人工检查点 1，必需） | Owner 看隐去来源、打乱顺序的三个方向，选一个或组合（如“B 但用 A 的首屏”），写一句理由；之后才揭示 Agent 的推荐与取舍，允许改选 | 选择记录 |
| 5. 固化 | 改 `global.css` 的 token 块；派生站 `DESIGN.md` 只写意图、规则与偏好、命名的反套路和所对照的金标样例，不复制 Token | `global.css` token 块 + `DESIGN.md` |
| 6. 实现与审查 | 独立审查者按派生站 `DESIGN.md`、命名失败清单和[速查表](#设计审查速查表)逐条核对，每条注明所需证据（截图、HTML 或运行）；最多 3 轮后交给人 | 审查记录 |
| 7. 对照（人工检查点 2，可选） | 首批关键页完成后，Owner 并排看实现截图与选定方向，只回答“还是不是那个方向、哪里跑偏”；跑偏回到第 5 或 6 步 | 一句话结论 |

选择记录写选中方向、落选方向和一句理由，并注明是否在看到推荐后改选。跨站品味记录由 Owner 在仓库外保存，仓库不存放个人偏好。

比较候选时使用同一组事实、主要内容与视口，比较构图、图片角色、排版和密度的实际差异，不因删掉必要内容而误判某稿更好。默认模板如果最适合也可以采用；应指出具体哪里不合品牌或任务，而不是先淘汰“像模板”的方案。

Mood board 可用于沟通整体感受，Style Tiles 可将方向落实到字体、色彩、线条和界面元素。ImageGen 可作为构图、整页视觉目标或局部改稿的工具；Stitch 可用于页面布局与交互探索；Figma 按协作和精细编辑需要选用。这是按用途选择工具的建议，不是已验证的固定组合或能力排名；探索稿须标明假设，正式内容和实现仍需核对。

盲选之后，Agent 应看实际作品、给出推荐与具体取舍，不只把候选交给用户挑选。设计批评应指出位置、原因和改法；选定后围绕问题局部修改，保留已成立的优点。结构问题回到内容和布局，方向问题回到品牌与素材，实现偏差修实现。

静态图片可以作为高保真视觉目标，但不能证明交互、响应式、键盘、状态或 no-JS 行为。生成素材不替代业务证据，导出的代码不直接覆盖仓库；最终结果仍由真实页面及适用验证判断。

### 命名失败清单

方向检查和品味审查逐条判断下列失败是否出现，指出位置和改法，不给整体品味打分。反例截图待收集，收集后与金标样例放在一起。

| 名称 | 表现 | 反例 |
| --- | --- | --- |
| 编造 | 数字、认证、案例、客户 logo 或产能无法追溯到内容包 | 首屏写“20 年经验、500+ 客户、ISO 9001”，内容包里没有来源 |
| 模板脸 | 套用当期 AI 默认构图，换个行业仍成立 | 米白底、衬线标题加一个变色词、右侧卡片、实心按钮配描边按钮 |
| 装饰盖事实 | 图片、渐变或动效挤占产品身份、规格和 CTA | 首屏整屏氛围图，滚动后才知道卖什么 |
| 空洞 | 大留白和口号，没有型号、材料、应用或证据 | 三拍口号加一个按钮，下面是空白 |
| 盒子堆 | 内容全部装进等大卡片或卡中卡，规格被拆散 | 一张参数表被拆成十二张卡片 |
| 平 | 字号、字重和颜色没有层级，主要行动不唯一 | 首屏三个同样醒目的按钮 |
| 拼盘 | 区块像来自不同网站，Token、圆角、图片处理不统一 | 一段圆角阴影卡片接一段直角细线表格 |

### 双通道设计审查

新的整体视觉方案应由 Owner 或独立审查者复核；小范围调整按影响检查，不强制启动两个 Agent 或生成两份报告。审查区分以下两类判断：

| 通道 | 检查内容 |
| --- | --- |
| 品味审查 | 逐条对照命名失败清单和金标样例：层级、节奏、克制、模板感和买家理解成本 |
| 确定性审查 | 事实、对比度、键盘、状态、窄屏、no-JS、性能和浏览器行为；动效另需逐帧录制 |

主 Agent 综合两路结果，分别记录“必须修复”“可以接受”“不属于当前范围”。确定性检查通过不代表视觉方案有品味，品味认可也不代表运行行为成立。

## 设计审查速查表

- [ ] 首屏说清产品、买家和下一步；每个区块回答一个买家问题，规格、交付边界和证据没有被装饰掩盖；主要 CTA 只有一个且动作明确。
- [ ] 用户知道哪些元素可操作，操作后有反馈；错误可理解、可修复；默认、Focus、Loading、Error、Empty 等适用状态齐备，关闭动画仍能完成任务。
- [ ] 颜色、字体、间距、圆角、边框和阴影来自同一系统；相同语义的组件行为一致，强调色只强调必要内容，留白表达分组，不制造空洞。
- [ ] 未新增无必要依赖、客户端脚本或 island、动画；320px/375px、键盘、200% 缩放和 reduced-motion 均成立。
- [ ] 无 JavaScript 时正文和询盘入口可用，参考细节不损害性能。模块组合若像来自不同网站，退回筛选或统一 Token，不继续叠加装饰。

设计调整先读本文和[主题入口](../../src/styles/global.css)；涉及代码边界时再读[UI 实现规则](../../.claude/rules/ui-i18n-consent.md)。需要比较外部案例时，按任务查阅[设计参考](设计参考.md)；派生站改哪些文件见 [README 的派生站点改哪里](../../README.md#派生站点改哪里)，上线前提与证据见 [LAUNCH.md](../../LAUNCH.md)。历史视觉翻译、样稿和被否方向不作为当前规则。
